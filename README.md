## The problem this solves

Most retrieval systems answer every question. That is the problem.

An enterprise assistant that confidently invents an HR policy, or quotes a salary band
to someone not entitled to see it, is worse than no assistant at all — because people
act on it. The hard part of enterprise RAG is not finding text. It is knowing when the
retrieved text does not support an answer, and stopping.

This repository is the layer that decides whether an answer may be released.

## What happens when the system does not know

It says so, and that behaviour is measured rather than asserted.

The approved evaluation includes five questions the corpus deliberately cannot answer —
plausible questions about the fictional company with no supporting document anywhere.

> **All five were refused. None were answered.**

The blocking full-stack run uses the pinned OpenAI snapshot documented in the approved
baseline. Optional local-model runs are compatibility experiments, not published quality
evidence.

When evidence is weak but not absent, the system does not simply give up: it retries with
keyword retrieval, searches for supporting excerpts, and expands to neighbouring passages.
If it still cannot verify the answer, it routes to human review rather than releasing it.

## The test evidence

**[The full evaluation report is here.](https://beyondalgorithms2026-source.github.io/RAG_ENTERPRISE_LANGGRAPH_APP/evaluation/)**
It is generated from an explicitly approved full-stack baseline rather than written by
hand or inferred from an unapproved local run.

| | |
|---|---|
| Correct refusals | **5 of 5** |
| Overall quality | **25 of 25** in the approved full-stack baseline |
| Red-team scenarios | 18 deterministic mechanisms defended offline; RT-06 and RT-16 require live SQL proof |
| Automated tests | Counted by CI on each run; no stale total is published here |

The report publishes the pinned model, embedding, chunking, retrieval, prompt, and corpus
metadata needed to interpret the result. Baseline changes require an explicit reviewed
change and are never made automatically after a regression.

**The evaluation is checkable.** The corpus is synthetic and generated by the
[`corpus/generate_corpus.py`](https://github.com/beyondalgorithms2026-source/RAG_ENTERPRISE_STARTER/blob/main/corpus/generate_corpus.py)
script in the data-layer repository, so the source of every document is public. Every
question and expected answer is in `config/eval-set-northwind.json`.

## What this is NOT

- **Not a production or client deployment.** The data layer is available as a public
  Render Free portfolio demo over 28 synthetic documents, with a public governed UI at
  [`rag-enterprise-governance-demo.onrender.com/app`](https://rag-enterprise-governance-demo.onrender.com/app).
  It has no real users or real-workload evidence.
- **Not a general benchmark.** The approved v1 claim covers 25 questions on the isolated
  27-document corpus. The 90-case, 28-source v2 suite remains unapproved until its
  calibration completes. Both describe only this synthetic system.
- **Not a finished product.** Agentic actions (email, Slack, calendar) are deliberately
  non-dispatching: the approval, audit and policy machinery around them is real, the
  outbound effect is not.
- **Not a production accuracy claim.** The approved 25/25 result is specific to the
  versioned questions, corpus, prompts, model, and retrieval configuration recorded in
  the baseline.

## Architecture — three repositories, on purpose

```
    You ask a question
           │
    ┌──────▼──────────────────────────────┐
    │  Agent layer  (this repository)     │   decides whether an answer
    │  no database access whatsoever      │   may be released
    └──────┬──────────────────────────────┘
           │  MCP protocol, over a pipe
    ┌──────▼──────────────────────────────┐
    │  Integration layer  (MCP server)    │   read-only tool interface
    └──────┬──────────────────────────────┘
           │  HTTP
    ┌──────▼──────────────────────────────┐
    │  Data layer  (backend + Postgres)   │   owns auth, access control,
    │  access control enforced in SQL     │   retrieval, citations, audit
    └─────────────────────────────────────┘
```

**The split into three repositories is a deliberate architectural choice, not
disorganisation.** The agent layer holds no database credentials and has no route to the
data. It cannot read a document it is not given, and it cannot widen its own access,
because the code that enforces access lives in another system entirely.

The same boundary applies twice: **the agent also cannot choose its own retrieval
policy.** Reranking, query rewriting and similar controls are server-side settings an
operator manages, not parameters a caller can set. If a calling agent could turn a filter
off, then text injected into a document could change what the system retrieves — and any
guarantee that depends on retrieval behaviour would stop holding. See
[docs/retrieval-governance.md](docs/retrieval-governance.md).

The other two repositories:

- **[RAG_ENTERPRISE_STARTER](https://github.com/beyondalgorithms2026-source/RAG_ENTERPRISE_STARTER)** — the data layer: PostgreSQL + pgvector, SQL-level access control, retrieval and citations
- **[RAG_Langgraph_MCP_server](https://github.com/beyondalgorithms2026-source/RAG_Langgraph_MCP_server)** — the integration layer

## Setup

Requires Python 3.12, Docker, and [Ollama](https://ollama.com).

```bash
git clone https://github.com/beyondalgorithms2026-source/RAG_ENTERPRISE_LANGGRAPH_APP.git
git clone https://github.com/beyondalgorithms2026-source/RAG_Langgraph_MCP_server.git
git clone https://github.com/beyondalgorithms2026-source/RAG_ENTERPRISE_STARTER.git

python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ./RAG_Langgraph_MCP_server
pip install -e "./RAG_ENTERPRISE_LANGGRAPH_APP[dev]"
```

Copy `.env.example` to `.env` and set `RAG_AGENT_MCP_SERVER_REPO` to your clone of the
MCP server. There is no default — the app refuses to start without it and tells you so.

Verify the wiring without a database:

```bash
rag-enterprise-agent --check-config
```

For a full answer you also need the backend running with an ingested corpus; see the
[starter repository](https://github.com/beyondalgorithms2026-source/RAG_ENTERPRISE_STARTER)
for the database, corpus and seed steps.

The governed public UI is available at
[`rag-enterprise-governance-demo.onrender.com/app`](https://rag-enterprise-governance-demo.onrender.com/app),
and its synthetic data-layer API is available at
[`rag-enterprise-starter-demo.onrender.com`](https://rag-enterprise-starter-demo.onrender.com).
Either service may take about a minute to wake after inactivity on Render Free. Deployment
details and public boundaries are in
[`docs/runbooks/RENDER_PUBLIC_DEMO.md`](docs/runbooks/RENDER_PUBLIC_DEMO.md).

Run the tests — no Docker, no database, no model required:

```bash
pytest -q
rag-enterprise-agent --red-team
```

The offline P12 smoke coverage validates the evaluation mechanism. The separate P12B
workflow provisions APP, MCP, STARTER and PostgreSQL/pgvector for the real two-phase
25 + 65 question run. During transition, the owner-reviewed 25-case v1 baseline remains
the approved blocking evidence; a skipped, failed, or uncalibrated v2 run is never
reported as approved quality evidence.
